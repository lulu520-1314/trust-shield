### 1.3 三个关键判断

**判断一：不要做 AIGC 检测模型的军备竞赛。**
开源检测器在跨生成器泛化上普遍掉点，我们没有数据也没有算力去训 SOTA。而且黑盒检测器天然违背赛题的"可解释"要求。正确做法是**用取证信号（forensics）代替分类模型**：ELA、噪声残差、频域、CFA、拷贝-移动，这些方法本身就是可解释的，且 CPU 上毫秒级。

**判断二：真正的护城河在"跨层证据融合"，不在单点检测。**
单看 ELA 会误报高纹理区，单看困惑度会误判模板化的人类文案。但"ELA 高 + 噪声残差不一致 + 该区域恰好是功效宣称的对比图 + 文案含'7 天美白'"——这个组合的证据强度是压倒性的。**融合逻辑本身就是创新点**，也最好讲。

**判断三：把合规规则做进去，是性价比最高的差异化。**
《广告法》第九条绝对化用语、《化妆品监督管理条例》特殊化妆品注册要求、《化妆品功效宣称评价规范》——这三套规则是确定性的、可引用的、平台真实在用的。加一个规则引擎的成本很低，但它让作品从"技术 Demo"变成"平台愿意采购的审核工具"，直接抬高"落地价值"这一项。

### 1.4 范围裁剪（明确不做什么）

- ❌ 不做视频/直播内容鉴伪（赛题聚焦图文）
- ❌ 不做全网爬虫溯源（演示环境不可控，改为"跨样本比对"的轻量版本）
- ❌ 不训练/微调大模型（时间不够，且收益低于工程打磨）→ 预留接口，PPT 里写为"未来规划"
- ❌ 不做移动端
- ❌ 不做用户体系/数据库（单机内存态即可）

## 3. 取证模块（原设计四层，实际交付五维，新增一致性层）

### 3.0 统一的证据数据结构

所有工具必须返回同一结构，这是可解释性的工程基础：

```json
{
  "tool": "pixel.ela",
  "scene": "image",
  "score": 0.62,
  "confidence": 0.8,
  "summary": "图像存在 2 处重压缩误差异常区域",
  "regions": [
    {
      "id": "r1",
      "bbox": [312, 180, 96, 88],
      "region_score": 0.78,
      "mask_path": "cache/ela_mask.png",
      "evidence": ["该区域 ELA 误差为全图中位数的 3.4 倍", "边界呈像素级锯齿，符合拼接特征"]
    }
  ],
  "artifacts": {"heatmap": "cache/ela_heat.png", "chart": "cache/ela_hist.png"},
  "cost_ms": 180
}
```

`evidence` 是**给人看的一句话**，不是内部特征名。这是 Reporter 的原料，也是 UI 上可点击展开的条目。

### 3.1 像素层（pixel）

目标：回答「这张图**有没有被局部改过**、**是不是生成出来的**、**改在哪**」。

#### 3.1.1 ELA — 错误级别分析

- **原理**：JPEG 是有损压缩，不同区域因编辑历史不同，重压缩后的误差水平不同。篡改区域（贴入/重绘）与背景的"压缩响应"不一致。
- **实现**：
  ```python
  resaved = cv2.imdecode(cv2.imencode('.jpg', img, [cv2.IMWRITE_JPEG_QUALITY, 90])[1], 1)
  diff = np.abs(img.astype(np.int16) - resaved.astype(np.int16)).max(axis=2)
  diff = cv2.GaussianBlur(diff.astype(np.float32), (5,5), 0)
  # 分块统计 32x32，计算块均值的 z-score
  ```
- **输出**：热力图 + 16×16 分块 z-score 矩阵
- **局限**：原图为 PNG、或已多次压缩时几乎失效。**必须与其他信号联合**。
- **CPU 耗时**：约 40 ms（2000×2000）

#### 3.1.2 噪声残差一致性

- **原理**：真实照片的传感器噪声在全图近似平稳（同 ISO、同曝光）。拼接/重绘区域来自不同噪声源，残差方差会跳变；AI 生成的平滑区域残差偏低。
- **实现**：
  ```python
  denoised = cv2.fastNlMeansDenoising(colored, None, 10, 7, 21)  # 或用双边滤波加速
  residual = img - denoised
  var_map = block_variance(residual, block=32)
  mad = 1.4826 * np.median(np.abs(var_map - np.median(var_map)))
  z = (var_map - np.median(var_map)) / (mad + 1e-6)
  ```
- **判据**：`|z| > 3.5` 记为异常块；连续异常块合并为区域
- **局限**：暗部低信噪比容易误报 → 用亮度掩码排除过暗区域
- **CPU 耗时**：200–600 ms（`fastNlMeans` 较慢，演示时可切 `bilateralFilter`）

#### 3.1.3 频域指纹（AIGC 与重采样痕迹）

- **原理**：自然图像的功率谱近似 `1/f^α` 幂律；扩散模型生成图的高频衰减曲线更陡且更平滑；GAN 上采样会留下周期性峰值（棋盘格）。
- **实现**：
  ```python
  gray = cv2.cvtColor(img, cv2.COLOR_BGR2GRAY).astype(np.float32)
  F = np.fft.fftshift(np.fft.fft2(gray * hann_window))
  mag = np.log1p(np.abs(F))
  # 径向平均 → P(r)；拟合 log P(r) ~ -α log r
  # 检测：高频段能量占比、谱峰数量（去趋势后超过 3σ 的孤立峰）
  ```
- **特征**：`alpha`（幂律指数）、`hf_ratio`（高频能量占比）、`peak_count`、`peak_energy`
- **输出**：频谱图（**PPT 上非常好看的视觉素材**）+ 数值
- **局限**：经过强压缩或缩放后指纹会削弱 → 只作为辅助维度，权重较低
- **CPU 耗时**：120 ms

#### 3.1.4 CFA 插值一致性（加分项，可选）

- **原理**：真实相机经 Bayer 阵列插值，绿色通道与红蓝通道间存在周期性相关；AI 生成图无此结构。
- **实现（简化版）**：对残差图按 2×2 相位分组，计算组间方差比 `CFA_ratio`；真实图该比值显著偏离 1。
- **说明**：实现复杂度较高，列为 P2，时间紧则跳过，PPT 中写为"可扩展维度"。

#### 3.1.5 拷贝-移动检测

- **原理**：同一张图内部复制粘贴（如把"使用前"的瑕疵复制到别处）会产生重复的局部纹理。
- **实现**：
  ```python
  sift = cv2.SIFT_create(nfeatures=2000)
  kp, des = sift.detectAndCompute(gray, None)
  matches = BFMatcher(NN).knnMatch(des, des, k=50)   # 自匹配
  # ratio test 0.75 + 排除空间距离 < 60px 的匹配对
  # RANSAC 估计仿射变换 → 聚类 → 生成 copy-move mask
  ```
- **输出**：匹配连线图（直观）+ mask
- **CPU 耗时**：300–800 ms

#### 3.1.6 元数据与生成器指纹

- EXIF 缺失（尤其声称"实拍对比图"却无相机信息）→ 弱证据
- `Software` 字段命中 `Photoshop / Stable Diffusion / Midjourney / 美图` → 强证据
- 图片尺寸为 512/768/1024 等生成模型典型分辨率 → 弱证据
- **CPU 耗时**：< 10 ms

#### 3.1.7 像素层融合

```python
region_score = 0.30*ela + 0.35*noise + 0.15*freq + 0.15*copymove + 0.05*meta
```
- 各维度先归一化到 [0,1]（用分位数映射，阈值在自建验证集上标定）
- 生成统一 mask：各维度 mask 加权求和 → Otsu 阈值 → 形态学闭运算 → 连通域
- 连通域面积 < 0.5% 图面积的丢弃（降噪）
- 每个连通域输出一张"区域卡片"，含该区域在各维度的具体数值

> 权重的初始值来自经验，最终以自建验证集上的定位 IoU 为准做网格搜索，结果写进 PPT 的消融页。

### 3.2 语义层（semantic）

目标：回答「这段种草文案**是不是 AI 写的**、**哪几句最可疑**」。

#### 3.2.1 困惑度曲线（主信号）

- **原理**：语言模型对 AI 生成的文本"更不惊讶"——token 级 logprob 高且波动小（低困惑度、低 burstiness）；人类文本有口语跳跃、错别字、突发的短句，困惑度波动大。
- **实现**：
  ```python
  # GPT2-chinese (uer/gpt2-chinese-cluecorpussmall) 或 Qwen2.5-0.5B
  logprobs = model.token_logprobs(text)          # 逐 token
  window = 20
  ppl_curve = exp(-rolling_mean(logprobs, window))
  ```
- **特征**：
  - `ppl_mean`（越低越像 AI）
  - `ppl_std` / `burstiness = std/mean`（越低越像 AI）
  - `low_ppl_ratio`（PPL < 15 的 token 占比）
- **输出**：折线图（**PPT 上的"AI 文本平得像尺子"对比图，非常有说服力**）
- **注意**：必须用同一模型、同一 tokenizer；短文本（<80 字）不适用，需标记为"证据不足"
- **CPU 耗时**：1–3 s / 500 字

#### 3.2.2 文体特征（可解释性主力）

不需要模型，全是可数出来的东西：

| 特征 | 人类种草 | AI 种草 |
|---|---|---|
| 句长变异系数 | 高（0.4+） | 低（0.2 左右） |
| 具体成分/品牌密度 | 高 | 低（泛泛而谈） |
| 第一人称体验词 | "我用了两周…" | "这款产品…" |
| 三段式结构 | 少见 | 常见（总-分-总） |
| 绝对化用语 | 偶发 | 高频（"绝绝子""闭眼入"） |
| 数字/时间具体性 | "第 3 天" | "坚持使用" |

实现为特征向量 → 可作为 LightGBM 的输入，也可直接加权成 `style_score`（不训练也能用）。

#### 3.2.3 轻量分类器（可选，作为佐证）

- 特征：上述文体特征 + char 1-3gram TF-IDF（5000 维）
- 模型：LightGBM（CPU 秒级训练）
- 数据：HC3 中文子集（human vs ChatGPT）+ 自造样本
- **定位**：只作为佐证维度，权重不超过 0.25。理由：分类器容易过拟合到"特定模型的文风"，跨模型泛化差，且不可解释。

#### 3.2.4 输出

```json
{
  "tool": "semantic.aigc_text",
  "score": 0.71,
  "artifacts": {"ppl_curve": "cache/ppl.png", "sentence_heat": "cache/sent.png"},
  "sentences": [
    {"text": "坚持使用七天后，肌肤焕然一新", "score": 0.88, "reason": "PPL 12.3，低于全文均值 41%"}
  ]
}
```

### 3.3 行为层（behavior）

目标：回答「这些评论**是不是刷的**、**哪一批账号在刷**」。

输入退化策略：若 `comments.txt` 无账号/时间字段，则只用"模板聚类 + 情感一致性"两个维度，并在报告中明确说明"证据维度受限"——**主动暴露局限比假装全能更可信**。

#### 3.3.1 模板化聚类

- SimHash（64 bit）或 char-3gram MinHash → Jaccard 相似度
- DBSCAN 聚类（`eps=0.65, min_samples=3`）
- 簇内文本差异仅在于替换了形容词 → 判定为模板变体
- 输出：簇列表 + 每簇的代表文本 + 簇大小

#### 3.3.2 时间规律

- 输入时间戳序列 → 相邻间隔 → 变异系数 `CV = std/mean`
- 机器定时投放特征：`CV < 0.15` 且样本量 > 10
- 爆发式投放：滑动窗口内计数 > 均值 + 3σ
- 周期性：对间隔序列做 FFT，检测主频峰值
- 输出：时间轴散点图（**一眼就能看出"一条直线"或"一坨"**）

#### 3.3.3 情感与内容一致性

- 情感极性（可用简单词典，或复用 VLM）
- 全部同极性 + 文本长度均值 < 20 字 + 模板相似度高 → 刷单三连
- 评论是否提及商品具体细节（成分、色号、使用场景）→ 水军通常不提

#### 3.3.4 账号画像（若有账号字段）

| 信号 | 水军特征 |
|---|---|
| 昵称 | 随机串 + 数字后缀，信息熵高 |
| 头像 | 默认/缺失 |
| 注册时间 | 聚集在同一时间段 |
| 评论历史 | 只评某一品类/某几个商品 |
| 互动 | 点赞为 0，无回复 |

输出：账号风险分 + 高风险账号列表

#### 3.3.5 输出

```json
{
  "tool": "behavior.comments",
  "score": 0.83,
  "clusters": [{"id":"c1","size":27,"similarity":0.91,"template":"很好用，回购了","timestamps":"聚集在 12 分钟内"}],
  "artifacts": {"timeline": "cache/timeline.png", "scatter": "cache/cluster.png"}
}
```

### 3.4 逻辑层（logic）— VLM 语义核验

目标：回答「图文**是否自相矛盾**、宣称**是否夸大**、背书**是否可核验**」。

#### 3.4.1 图文一致性

模型：`qwen2.5vl:3b`（Ollama）
Prompt（固定模板，输出严格 JSON）：

```
你是化妆品广告审核专家。给定一条种草内容与其配图，请只依据图中可见信息判断。

【文案】{text}
【配图】使用前 / 使用后 对比图

请回答：
1. 图中可见的皮肤状态差异，是否足以支撑文案中的效果承诺？（0-1）
2. 图中是否存在修图痕迹：光影方向不一致、肤色过渡生硬、背景/发丝边缘变形、
   鼻翼与脸颊纹理不连续？（逐条列出，无则空）
3. 文案中提到的"专家/医生/机构/奖项"是否在图中或文案中有可核验信息？

严格输出 JSON：
{"effect_support": 0.0, "edit_signals": [{"type":"","where":"","desc":""}],
 "credential_verifiable": false, "reason": ""}
```

- 用 `format=json`（Ollama 的结构化输出）保证可解析
- 失败重试 1 次，仍失败则降级为"逻辑层不可用"，并在报告里标注（**不静默失败**）

#### 3.4.2 输出

```json
{
  "tool": "logic.vlm_consistency",
  "score": 0.55,
  "issues": [
    {"type": "effect_overclaim", "desc": "图中肤色差异约 1 个色阶，文案称'7 天白 3 个度'"},
    {"type": "light_inconsistent", "desc": "使用后照片光源来自右上方，使用前来自正前方"}
  ]
}
```

> 这一层的价值不在于"多准"，而在于**它能说出人话的理由**，且与像素层的客观信号互相印证——"VLM 说光影不一致" + "噪声残差在面部区域异常" = 强证据。

### 3.5 规则层（rules）— 美妆合规引擎

纯规则，确定性，零算力。

#### 3.5.1 规则库

| 规则组 | 依据 | 示例命中 |
|---|---|---|
| 绝对化用语 | 《广告法》第九条 | 最、第一、顶级、国家级、绝无仅有、独一无二、首个、首选、冠军、史上最低 |
| 医疗作用宣称 | 《化妆品监督管理条例》第 43 条 | 治疗、消炎、杀菌、抗敏、药妆、医学护肤、修复（医学语境）、生发 |
| 特殊化妆品未标批号 | 条例第 16 条 | 美白、祛斑、防晒、染发、烫发、防脱 → 需"国妆特字" |
| 功效宣称无依据 | 《化妆品功效宣称评价规范》 | "7 天见效""28 天换肤"等时限承诺、无评价报告编号 |
| 虚假背书 | 《广告法》第二十八条 | "XX 医院皮肤科主任""诺贝尔奖团队""中科院研发"（无可核验来源） |
| 前后对比图规范 | 平台社区公约 | 未标注"效果因人而异"、使用明显修图对比 |

#### 3.5.2 实现

- 词表用 YAML 维护（便于扩写与展示）
- 正则 + 上下文窗口（"修复"在"修复屏障"里是合规的，在"修复痘坑"里是医疗宣称 → 用窗口内的搭配词判定）
- 每条命中的输出：`{rule_id, clause, matched_text, span, risk_level}`

#### 3.5.3 输出

```json
{
  "tool": "rules.beauty_compliance",
  "score": 0.9,
  "hits": [
    {"rule": "absolute_wording", "clause": "《广告法》第九条", "text": "全网最低价", "risk": "high"},
    {"rule": "special_cosmetic_no_approval", "clause": "《化妆品监督管理条例》第十六条",
     "text": "7 天美白", "risk": "high", "note": "美白属特殊化妆品，需标注国妆特字号"}
  ]
}
```

> 规则层是"落地价值"页的核心论据：它输出的不是概率，而是**可以直接写进处置工单的违规条目**。

## 4. 证据融合与风险分级

### 4.1 融合公式

```
RiskScore = Σ w_i · s_i          s_i ∈ [0,1]（各工具归一化分数）
```

| 场景 | 权重配置 |
|---|---|
| 种草图文核验 | 像素 0.35 / 语义 0.20 / 逻辑 0.25 / 规则 0.20 |
| 评论区核验 | 行为 0.75 / 语义 0.15 / 规则 0.10 |
| 素材鉴伪 | 像素 0.80 / 逻辑 0.15 / 语义 0.05 |

### 4.2 分级与处置

| 分数 | 等级 | 处置建议 | UI 表现 |
|---|---|---|---|
| ≥ 0.75 | 高风险 | 下架 + 转人工复核 + 账号降权 | 红色 + 阻断图标 |
| 0.45–0.75 | 中风险 | 限流 + 要求补充功效依据 | 橙色 + 警示 |
| < 0.45 | 低风险 | 通过，保留抽检 | 绿色 + 通过 |

### 4.3 置信度校准

- 用自建验证集（≥200 条）做分位数映射：`calibrated = ECDF(raw_score)`
- UI 上同时展示"原始分"与"校准后置信度"，并在 tooltip 说明"基于 N=xxx 样本校准"
- **不要伪造精确数字**：标注置信度的样本基础，这本身就是可信度的一部分

### 4.4 证据覆盖率（自评指标）

```
coverage = 该判定引用的独立证据条目数 / 该场景应检查的维度数
```
要求：任何"高风险"判定必须 ≥ 2 个维度的支持，否则自动降级为"中风险（证据不足）"。
这条规则写进系统里，也写进 PPT——**它证明我们的系统知道自己什么时候不确定**。

## 5. Agent 编排设计

### 5.1 为什么不用自由 ReAct

自由 ReAct 在演示现场会翻车（循环调用、幻觉工具、耗时不可控）。改用**受控 DAG**：

```
输入 → 场景分类(规则优先, LLM兜底) → 固定工具集 → 并行执行 → 融合 → 报告
```

LLM 只做三件"它擅长且不会出错"的事：
1. 场景分类（含混合场景）
2. 把结构化证据翻译成自然语言报告
3. 基于证据上下文的问答

### 5.2 工具注册表（JSON Schema）

```json
{
  "name": "pixel_forensics",
  "description": "对图片进行取证分析，返回篡改区域与各维度分数",
  "parameters": {
    "type": "object",
    "properties": {
      "image_paths": {"type": "array", "items": {"type": "string"}},
      "profile": {"type": "string", "enum": ["full", "fast"]}
    },
    "required": ["image_paths"]
  }
}
```

### 5.3 报告生成 Prompt

```
你是内容审核专家。以下是系统对一条内容的取证结果（JSON）。
请生成一段 150 字以内的审核结论，要求：
1. 先给结论（风险等级），再给 2-3 条最关键的依据，每条必须引用证据中的具体数值或位置；
2. 不确定的地方明确说"证据不足"，不要编造；
3. 不使用"可能""也许"等模糊词堆砌，要给出判断。
```

### 5.4 对话状态

```
idle → analyzing（进度条 + 流式证据） → reported（结论卡） → qa（基于 evidence 上下文）
```
追问时把 `evidence_store` 全量注入（通常 < 3k token），保证回答有据可依。

### 6.1 三栏布局

```
┌──────────────┬───────────────────────────┬──────────────────┐
│  ① 输入区     │  ② 证据面板                │  ③ 判定与对话     │
│              │                           │                  │
│ [拖拽上传]    │  [原图 + 篡改热力图叠加]    │  风险等级 高      │
│ 场景自动识别  │  可切换：ELA/噪声/频域/CMA  │  ●───────○ 0.82  │
│ 示例样片 ×6   │                           │                  │
│              │  [证据雷达图 5 维]         │  依据：           │
│              │                           │  ▸ ELA 3.4σ      │
│              │  [可疑句高亮]              │  ▸ 噪声残差偏差41%│
│              │                           │  ▸ 违反广告法第九条│
│              │  [评论区聚类散点 + 时间轴]  │                  │

│              │                           │  [追问框]         │
└──────────────┴───────────────────────────┴──────────────────┘
```

### 6.2 三个"哇"时刻（视频里必须拍到）

1. **热力图叠加**：拖动透明度滑块，红色区域正好落在"使用后"照片的脸颊/下巴——评委一眼看懂。
2. **点击证据联动**：点右侧"噪声残差偏差 41%"，中间热力图自动高亮对应区域。
3. **对话追问**："为什么判定这张图被改过？" → 系统逐条引用证据回答，而不是复述结论。

### 6.3 技术实现

- 后端：FastAPI + SSE 流式推送进度
- 前端：原生 HTML + Alpine.js + Tailwind（CDN），图表用 ECharts CDN
- **不引入前端构建工具**——减少环境风险，评委/自己换机器也能跑
- 离线兜底：所有 CDN 资源下载到本地 `static/vendor/`，演示现场断网也能跑

## 7. 数据方案

赛题不提供标注数据，数据是**交付物之一**，也是评"严谨度"的地方。

### 7.1 数据来源

| 类型 | 来源 | 用途 | 数量 |
|---|---|---|---|
| 真实文案 | 公开平台种草文本（仅作研究，脱敏） | 负样本 | 100+ |
| AI 文案 | Qwen2.5 生成（多风格 prompt：软广/测评/避雷/成分党） | 正样本 | 100+ |
| 真实图片 | COCO / GenImage real 子集 / 公开商品图 | 负样本 | 100+ |
| AIGC 图片 | GenImage 生成子集 / SD 生成（Colab 免费额度批量出图） | 正样本 | 100+ |
| 篡改图片 | 脚本合成：seamlessClone 换肤色、局部 inpainting、复制-移动 | 正样本 + mask | 80+ |
| 评论区 | 脚本模拟：模板库 + 时间扰动 + 账号池 | 正样本 | 30 组 |

### 7.2 合成管线（`data/build_dataset.py`）

```
1. 读基础图 → 随机选区域 → 三种篡改算子之一 → 保存图 + mask
2. 生成对应 meta.json（fake_type / difficulty / mask_path / source）
3. 难度分级：
   easy   = 单算子 + 大面积 + 无二次压缩
   medium = 单算子 + 小面积 + JPEG 二次压缩
   hard   = 多算子叠加 + 边缘羽化 + 全图重压缩
```

### 7.3 公开数据集交叉验证（关键，防止"自己出题自己满分"）

| 层 | 外部验证集 | 指标 |
|---|---|---|
| 像素层 | GenImage val（real vs SD） | 图像级 AUC |
| 像素层定位 | CASIA v2 / COVERAGE | 像素级 IoU / F1 |
| 语义层 | HC3 中文（human vs ChatGPT） | 文本级 AUC / F1 |

**这三行数字必须出现在 PPT 的评测页**——它是"我们不是自说自话"的唯一证据。

### 7.4 提交测试包结构（严格对齐赛题）

```
测试数据包/
├── sample_001/
│   ├── post/
│   │   ├── content.txt        # 正文（标题+正文 + 宣称）
│   │   ├── image_1.jpg        # 使用前
│   │   └── image_2.jpg        # 使用后
│   ├── comments.txt           # 评论区（含账号/时间，制表符分隔）
│   ├── meta.txt               # 场景/来源/是否伪造/伪造方式/难度
│   └── mask.png               # ground-truth 篡改区域（伪造样本才有）
├── sample_002/ ...
└── README.txt                 # 数据集说明 + 评测脚本用法 + 指标定义
```

- 规模：**50 条**（种草图文 20 / 评论区 15 / 素材鉴伪 15），难度分布 3:4:3
- `meta.txt` 用 `key: value` 格式，字段固定，便于评委机器读取
- README 里附一段 `eval.py` 用法：评委可以把我们的系统输出与 mask 对比，自己算 IoU

> 这一步是"专业度"的体现：**你不仅给了数据，还给了评测方法**。

## 8. 评测方案

### 8.1 指标定义

| 指标 | 定义 | 目标值（初版） |
|---|---|---|
| 检测 F1 | 样本级二分类 | ≥ 0.80（外部集） |
| 定位 IoU | mask 交并比 | ≥ 0.35 |
| 证据覆盖率 | 判定引用维度 / 应查维度 | ≥ 0.80 |
| 端到端时延 | 单样本（CPU） | ≤ 25 s（含 VLM） |
| 误报率 | 真实内容被判高风险 | ≤ 10% |

### 8.2 消融实验（PPT 用）

| 配置 | F1 | IoU | 说明 |
|---|---|---|---|
| 仅语义层 | — | — | 基线 |
| 仅像素层 | — | — | |
| 像素 + 语义 | — | — | |
| 全部维度 | — | — | 完整系统 |

### 8.3 人工可解释性评分

找 3 位非本团队成员，看 10 条判定，按 1–5 分评"证据是否足以支撑结论"。**这个数字放在 PPT 上比任何模型指标都有说服力。**

## 9. 技术选型与 CPU 预算

### 9.1 选型

| 组件 | 选型 | 许可 | 备注 |
|---|---|---|---|
| 编排 LLM | Qwen2.5-3B-Instruct (Q4_K_M) | Apache-2.0 | 7B 太慢，3B 够用；可配置切换 |
| 视觉 LLM | Qwen2.5-VL-3B (Q4) | Apache-2.0 | Ollama `qwen2.5vl:3b` |
| 困惑度模型 | GPT2-chinese-cluecorpussmall | MIT | 比 0.5B LLM 快，够用 |
| 图像处理 | OpenCV + numpy + scikit-image | BSD | |
| 分类器 | LightGBM | MIT | 可选 |
| 后端 | FastAPI + uvicorn | MIT | |
| 前端 | 原生 + Alpine + ECharts | | 无构建步骤 |
| 推理运行时 | Ollama（或 llama.cpp） | MIT | 本地、离线 |

### 9.2 时延预算（16GB 内存笔记本，8 核 CPU）

| 步骤 | 耗时 |
|---|---|
| 像素层（全量） | 0.8–1.5 s |
| 语义层（500 字） | 1–3 s |
| 行为层 | < 1 s |
| 逻辑层 VLM（1 图） | 15–35 s |
| 报告生成 | 2–5 s |
| **端到端** | **20–45 s** |

### 9.3 降级策略（保证演示不卡死）

1. VLM 超时 30 s → 跳过逻辑层，报告标注"语义核验未完成"
2. `fast` profile → 跳过 `fastNlMeans`，用 `bilateralFilter`，总时长砍半
3. 演示用样例**预跑缓存**（结果落盘，演示时秒出），但保留"实时跑一条"的环节证明是真的
