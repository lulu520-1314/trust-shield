## 二、调参记录（为什么最后长这样）

这些都是实测踩出来的，写进答辩材料比「用了什么算法」更有说服力：

1. **方差类指标必须在对数域做 z-score。**
   皮肤特写的 Laplacian 方差中位数约 11760，磨皮区约 2.1。线性域里 MAD 被长尾拉爆，
   z 只有 -0.68；取 log10 后同一位置 z = -5.15，才能被检出。

2. **磨皮只在肤色区生效。**
   浅色背景本身没有纹理，不设肤色门控会把白墙判成「被磨皮」。
   用 YCrCb 椭圆肤色模型做块级门控后，干净图片的误报从 0.60 降到 0.19。

3. **单信号异常一律不定位。**
   正常高纹理照片的 ELA 天然偏高。要求 ELA / 噪声 / 磨皮至少两路在同一区域同时异常，
   才认为是「证据确凿」的篡改区域——这条规则把误报从「每张图都有」压到「干净图几乎为零」。

4. **频域只惩罚「过于平滑」。**
   功率谱斜率 α 偏低是高纹理的正常表现（手部特写 α≈1.15），早期双向惩罚导致所有
   皮肤特写都被判异常；改成只惩罚 α > 2.4 后消失。

5. **羽化半径决定检测上限。**
   合成样本时把羽化设成 26 px，篡改区域扩散到半张图，全图中位数被带偏，局部对比直接失效。
   真实修图的选区边界远比这锐利——这也解释了为什么「整体磨皮」比「局部精修」更难检测。

6. **证据卡的出卡门槛必须高于分档边界。**
   文体分 43/100 属于低档，旧逻辑却在 35 分就出「模板化」卡，于是出现
   「低风险 + 模板化」的自相矛盾。现在出卡门槛 55 分，像素层同步抬高
   （噪声 0.55 / 磨皮 0.50 / ELA 0.50），保证**卡片出现时结论一定不是低风险**。

7. **否定语境不是宣称。**
   「提亮效果我确实没看出来」曾被解析成「宣称提亮 1 个度」，导致对照组被误判夸大 3 倍。
   现在宣称解析会检查上下文里的否定词。

8. **结论等级不能和证据矛盾。**
   出现 ≥2 条高危证据时不允许停留在低风险；模板簇覆盖率与相似度达标时直接升级为高风险
   （确证性证据）。

## 六、v0.4：判定依据改为论证式

原实现把维度分再抄一遍（「像素 54、文本 61…」），用户反馈「太敷衍」「和右边重复」。

现在改为三段式：

1. **结论**（等级 + 分数）
2. **疑点论证**：从 ② 的证据里取（像素同区异常、图文色差对比、模板簇 + 投放节奏 + 账号画像），
   写成因果链，而不是罗列数值
3. **判定规则**：说明阈值与互证条件，解释为什么是这一档

低风险时反向写：列出检查了哪些维度、各自结果、为什么都没到阈值。

技术要点：叙事函数不再接收「维度列表」，而是接收完整 `dims` 与 `findings`，
并额外保存 `dims["pixel"]["worst"]`（最可疑那张图的六维明细），供论证时引用。


## 七、v0.5：文档导入

文案 / 评论不再只能粘贴。新增 `POST /api/extract`：

- `.txt` / `.md` / `.csv`：按 `utf-8-sig → utf-8 → gb18030 → big5` 顺序试解码，
  中文 txt 常见的 GBK 编码不会乱码；
- `.docx`：`.docx` 本质是 zip，用标准库 `zipfile` + `ElementTree`
  直接读 `word/document.xml`，**不引入 python-docx 依赖**；表格里的文字也会被抽出；
- `.doc` / `.pdf`：明确返回「请另存为」，而不是静默失败；
- 上限 8 MB / 2 万字，超出截断并在界面提示。

前端：输入框右上角「导入文档」按钮 + 拖拽导入，两条路径共用同一个 `importDoc()`。


## 八、v0.6：修掉 ELA 的 z 分数退化（并如实下调指标）

**问题**：`_zscore()` 里 `mad = median(|v-med|) * 1.4826 + 1e-6`。
当画面足够均匀（大片同色皮肤/背景）时 MAD 退化为 0，除数变成 `1e-6`，
任何微小灰度波动都被放大成天文数字——真实皮肤特写样本上出现过 `z = 876445.75`，
并被判成「存在重压缩误差台阶」。

**证据**：统计全部 50 条样本的 ELA 绝对幅度（dev98，单位灰阶）：

| | 伪造样本 | 真实样本 |
|---|---|---|
| dev98 中位数 | 0.93 | 0.94 |
| dev98 范围 | 0.35–3.06 | 0.40–1.94 |

两者**完全重叠**——ELA 在这批数据上根本没有区分力，此前的素材场景召回全部来自 z 爆炸。

**改动**：
1. `_zscore()` 的 MAD 下限从 `1e-6` 提到 `1e-3`，并截断到 ±200；
2. ELA 增加**绝对幅度闸门**：块间起伏（dev98）`< 1.5` 灰阶时直接判 0 分，
   不再让 z 分数单独决定结论；
3. 尝试过用分位数（p90 的 2%）做尺度下限，结果连噪声/磨皮两个检测器一起被削弱，
   素材场景召回直接归零——**已回退**，只保留 MAD 下限这一处最小改动。

**代价**：素材场景失去（本来就虚高的）检出，整体指标下降：

| 指标 | 修正前 | 修正后 |
|---|---|---|
| Precision | 0.810 | 0.765 |
| Recall | 0.607 | 0.464 |
| F1 | 0.694 | 0.578 |
| 素材场景 F1 | 0.53 | 0.00 |

**结论**：素材场景目前只能作为辅助筛查，不作为独立结论；已在 README 与 PPT 中如实标注。
教训是——**评估集里一定要有「真样本」，否则一个纯噪声的特征也能在伪造集上刷出高分**。

## 三、已知局限

- 整体调色 / 全图磨皮类修图召回偏低：局部对比失效，只能靠频域给弱提示
- 极端微距照片（毛孔比检测块还大）下，磨皮检测会失灵
- 同一张图被当作「前后对比」时会误报一次「前后图为同一画面」——这个判断本身是对的，
  但对「合法修图」缺乏区分能力
- 阈值是在自建合成数据上标的，换到真实平台数据需要重标
- 定位输出是外接矩形而非像素级 mask，IoU 只有 0.23
