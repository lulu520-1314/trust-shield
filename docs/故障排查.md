# 故障排查与已知问题

## 一、听到"念稿子"的声音（重要）

**现象**：打开产品后，浏览器一直重复朗读某些固定内容，但页面上找不到任何播放按钮。

**结论：不是本产品发出的。** 本产品代码里没有任何音频 / TTS / `speechSynthesis` / `<audio>` 调用
（全库检索 `speech|audio|.play(|tts` 零命中），页面也不含被朗读的文案。

**这次排查的实测证据**（Windows Core Audio 会话枚举）：

```
音频会话数: 4
ProcessId ProcessName Peak Active
     9560 chrome        36   True     ← 唯一在发声的进程
    27196 WeChatAppEx    0   False
    11896 taskhostw      0   False
    10052 chrome         0   True
```

连续采样 6 次：`11% → 0 → 6% → 9% → 58% → 20%`，是断续的语音节奏，来自
`chrome.exe --profile-directory="Profile 7"` 这个**另一个 Chrome 窗口**。
该窗口的会话文件里有这些标签页：

```
changjiang.yuketang.cn   雨课堂（网课视频）
www.doubao.com           豆包（AI 助手，支持语音朗读）
xgzx.ouc.edu.cn / my.ouc.edu.cn / math.ouc.edu.cn
127.0.0.1:8899           本产品
```

**怎么自己定位（10 秒）**：

1. 右键任务栏音量图标 →「打开音量合成器」（Win11：设置 → 系统 → 声音 → 音量合成器），
   看哪个应用在跳音量条
2. 或在 Chrome 里找标签页上的**小喇叭图标**，点一下会跳到发声的那个标签
3. 或打开 `chrome://media-internals`，能看到正在播放的媒体和所在的页面

**常见来源**：网课/视频没关、AI 助手的语音播报、浏览器朗读类扩展、PWA 后台播放。

## 二、产品自身的常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| 点示例没反应 | 服务窗口被关闭 | 重新双击 `start.bat` |
| 第二次点同一示例秒出 | 正常，走内存缓存 | 演示时正好用 |
| 对话没回答 | 还没跑过核验 | 先点一次示例，问答基于当前报告 |
| `address already in use` | 8899 被占用 | `python -m uvicorn app.server:app --port 8900` |
| 页面样式错乱 | 浏览器缓存了旧 CSS | `Ctrl + F5` 强制刷新 |
| 上传大图慢 | 自动缩到 1200px 处理 | 正常，几秒内 |

## 三、v0.2 修复的问题（2026-10-19 晚）

用 CDP 驱动无头 Chrome 自动点了一遍全流程，发现并修复：

1. **热力图跨图串台**
   `ela.png / noise.png / smooth.png` 文件名固定，两张图互相覆盖。
   切换「使用前 / 使用后」时，看到的是另一张图的取证结果。
   → 改为按文件指纹命名（`<hash>_ela.png`），每张图独立。

2. **切换场景不清空输入**
   从「图文」切到「评论」，上一篇文案还留在框里，再点核验会用旧文案。
   → `reset()` 里清空两个文本框、清空图表、移除残留的图片切换按钮。

3. **示例按钮重复出现两组**
   带 `?scene=` 参数打开时，初始化触发两次样本加载并发追加。
   → 场景已由 `setScene` 加载时不再重复调用；并加场景校验丢弃过期响应。

4. **图片切换按钮与热图视角按钮长得一样**
   两组按钮都用 `.chip.active`，同时高亮，分不清"选中哪张图"和"选中哪个视角"。
   → 新增 `.imgtab` 描边样式，并加竖线分隔。

5. **切场景瞬间能点到上一个场景的示例**
   列表在请求返回后才清空，存在一个可点击的时间窗。
   → 请求发出前先清空列表。

6. **favicon 404**
   → 内联 SVG 图标。

7. **控制台警告**
   评论完全相同时 `TruncatedSVD` 报 `invalid value encountered in divide`。
   → 局部屏蔽警告。


8. **「使用前/使用后」两个槽位含义不清**
   用户不知道能不能只填一张。
   → 加「必填 / 选填」徽标 + 一行说明；只填一张时，报告里显式写出「未提供对比图」，
   而不是静默跳过一致性维度。

9. **量化美白宣称漏检**
   「七天白三个度」这种没有"美白"二字的量化承诺，原正则匹配不到。
   → 补 `白 N 个度/色号/色阶` 规则。


10. **分制不统一**
    仪表盘显示 14，旁边写 0.14/1.00，维度条又是 0.20/0.43，三种写法混在一起。
    → 全站统一 0–100，仪表盘标注 `/ 100`，维度条加「低/中/高」标签和一行图例。

11. **维度分没有解释**
    用户看到 0.413 不知道是好是坏。
    → 每个维度标等级；上方加「维度分 0–100，越高越可疑」。

12. **「0 分」与「未参与」混淆**
    文案不足 40 字时文本文体算不出来，界面显示 0，看起来像"算过且没问题"。
    → 不可用的维度显示虚线条 + 「未参与」。

13. **素材鉴伪场景仍显示「使用前/使用后」**
    → 槽位标签按场景切换为「待检素材」，并加「配文（选填）」字段标签。

14. **对话只认三个固定问题**
    意图匹配顺序有误：「文本文体怎么算」被「怎么算」抢先匹配成评分说明；
    「为什么判这个等级」「改在哪一块」根本匹配不到，全部落到同一段兜底话术。
    → 重排意图优先级（具体维度优先）、补 11 类意图、加关键词检索兜底、加可点击的建议问题。


15. **图文一致性只给分数，看不出比对过程**
    → 新增「图文一致性比对」面板：实测 ΔE / 宣称 ΔE 两根条 + 夸大倍数 + 两图光照差。
    文案没有量化宣称时，面板写明「本次只测量了色差，未做夸大比对」，不再只给一个 0。

16. **「0 分」与「未参与」仍会混淆**
    → 不可用维度显示虚线条 + 「未参与」；单图场景额外给一张「未提供对比图」提示卡。

17. **43 分的文案被贴上「模板化」标签**
    证据卡的触发门槛是 35 分，而 45 分以下都算低风险——于是出现「低风险 + 模板化」的自相矛盾。
    → 出卡门槛抬到 55 分；标题改为「文案文体偏模板化」，并注明「越高越像模板/AI 生成」。
    同时把像素层的出卡门槛整体抬高（噪声 0.55、磨皮 0.50、ELA 0.50），
    避免弱信号在低风险结论旁边制造恐慌。

18. **输入框偏小、可无限拉伸**
    → 默认高度 96 → 150px，上限 420px，只允许垂直缩放（`resize: vertical; min-height; max-height`）。

19. **顶栏中间留白**
    → 放入四步流程指示（输入 → 取证 → 定级 → 处置），随状态高亮，既填充空位又提示当前阶段。


20. **同一指标在两个位置重复**
    图文一致性既在中间面板、又在右侧维度条；合规命中既在证据卡、又在右栏。
    → 指标只保留一处：一致性并入维度条（带 summary），合规只在右栏。

21. **判定依据过于单薄**
    低风险只输出一句「未发现异常特征」。
    → 改为「逐维实测 + 判定逻辑」两段，每个维度给出实测值与阈值关系。

22. **短文本被直接判「未参与」**
    33 字的配文算不出文体分，界面显示「未参与」，用户以为功能坏了。
    → 门槛降到 20 字；单句时剔除句长/段落类特征，标「短文本」但不放弃计算。

23. **合规命中显示碎片词**
    卡片上写着「时限性功效承诺：白一个度」，像口语梗。
    → 规则改名「量化功效承诺缺乏依据」；按句读截取所在小句，显示为「命中原文『7 天就能白一个度』」。


24. **特征贡献度图表没有说明，也没被用上**
    一排柱子只有数字（0.179、0.09…），不知道是什么单位、和结论什么关系，像装饰。
    → 图表上方加标题与一行说明（文体分多少、主要推手是谁、占比多少）；
    柱子标签改为「贡献值 · 占比」；文案特征从 9 条收敛到贡献前 5 条；
    低分时说明改为「各特征贡献均偏低，未形成模板化证据」，让图表也能解释「为什么没判」。
    去掉横轴刻度（数值已标在柱子上，横轴只会被版面裁掉）。

25. **流程条第 4 步「处置」看起来永远不亮**
    完成判定后第 4 步只是细描边（`.fs.on` 非常弱），而前 3 步是实心绿，视觉上像没激活。
    → 当前步骤改成实心琥珀色 + 外发光，与「已完成」的绿色区分开：
    第 4 步在报告生成后点亮，表示「现在处于处置阶段」。

26. **页签图标与页头 Logo 不一致**
    favicon 是单独的盾牌 emoji，页头是「渐变方块 + emoji」，两者观感不同。
    → 统一成同一枚内联 SVG（蓝绿渐变圆角方块 + 白色盾牌轮廓），
    页头 `.brand .logo` 与 `<link rel="icon">` 用同一路径，不再依赖系统 emoji 字体。


27. **导入的中文 txt 是乱码**
    很多 Windows 下的 txt 是 GBK 编码，直接按 UTF-8 读会变成乱码。
    → 后端按 `utf-8-sig → utf-8 → gb18030 → big5` 依次尝试，都失败才用 `errors="ignore"`。

28. **`.docx` 不想装 python-docx**
    → 用标准库解压取 `word/document.xml`，正则/ElementTree 抽 `<w:t>` 文本，
    表格单元格同样能拿到；只解析正文，不处理图片与批注。


29. **真实照片被判「重压缩误差台阶」，且 z 值离谱（如 876445）**
    根因：稳健 z 分数在中位数/MAD 退化时除以 `1e-6`，把亚灰阶波动放大成噪声。
    → MAD 下限提到 `1e-3` 并截断 ±200；ELA 另设绝对幅度闸门（dev98 < 1.5 灰阶判 0）。
    验证：`python eval/run_eval.py`，素材场景应从「虚高的 0.53」回到真实的 0.00。

30. **改 z 分数的尺度下限，为什么反而把召回改没了**
    一开始用 `max(mad, 2% × p90)` 做下限，噪声与磨皮两个检测器共用 `_zscore`，
    一起被削弱，素材场景召回直接归零。
    → 只保留最小改动（`max(mad, 1e-3)`），把绝对幅度判断放到 ELA 自己身上，
    不要动公共函数的行为。
